覆盖 SSH/Bash 和 MySQL 操作。环境类别决定展示方式和谨慎程度，执行范围以用户当前任务和已有授权为准。与其他 SSH/MySQL 技能一起安装和使用。

## 确定环境

从用户说明、对话上下文和目标相关 `AGENTS.md` 获取类别，当前用户明确说明优先。分类信息由这些来源提供，执行规则由本 skill 定义。已经在同一对话中确定的目标类别，后续沿用，不重复询问。用户修正类别、实际目标改变或出现直接冲突的信息时才重新判断。

以实际连接目标识别同一服务器，包括 SSH 用户、主机、端口和跳板机后的目标 endpoint。别名解析到同一目标时沿用原分类，共享跳板机的不同目标分别记录。对话交接或压缩时保留已经确认的分类。

信息不足时，使用 Secure Enclave / Touch ID 等 secure 指纹授权的服务器（无论是原生 `SecurityKeyProvider` 的 `sk-ecdsa`，还是通过 `keychain-pkcs11` / `--secure-ecdsa-dir` 使用的 `ecdsa-sha2-nistp256`）均默认按正式服务器处理。普通 `known_hosts` 主机指纹验证不触发此默认规则。其他无法确定的目标询问用户属于独占测试、非独占测试还是正式服务器，等待回答后再连接，同一对话对同一目标只询问一次。“测试服务器”本身未说明独占性。

## 执行方式

- 独占测试服务器允许在当前任务范围内批量操作，按需展示。临时文件、预先展示和内容变化后重新展示均为可选。用户对具体任务另有要求时遵从该要求。
- 非独占测试服务器先完整展示本次操作文件和实际执行命令，再执行同一文件，内容变化后重新展示。
- 正式服务器遵循同一文件和展示流程，并提前说明读写范围、导出位置、锁或其他相关影响，谨慎执行。已有明确授权的操作展示后执行，缺少必要授权时询问用户。

## 单文件审阅

一事一个临时文件，内容仅包含当前任务必要的操作。Bash 使用 shell 文件，SQL 使用 SQL 文件，MySQL Shell utility 使用 JS 文件或包含本次 CLI 调用的 shell 文件。复杂目录树、manifest、额外 launcher 或拆分文件仅在用户明确要求时创建。工具内部的隧道和凭据资源由既有脚本管理。

先创建文件，再读取它，将完整内容用用户可见的代码块展示，同时展示实际执行命令。仅调用 `cat`、引用文件名或给出链接不足以替代完整展示。Bash 和 SQL 都添加必要注释，说明目标、目的、筛选条件、影响范围和输出位置。密码、私钥和令牌通过既有凭据机制读取。

展示内容就是执行内容。执行前核对文件字节与展示版本一致，可以记录并检查哈希。内容变化后重新展示。新增诊断、查询、修复和验证操作各自遵循同一规则。避免展示后通过 `eval`、字符串拼接、下载脚本或未展示的临时文件增加操作。已安装的连接与凭据脚本作为固定工具依赖，本次修改它们时展示相关变更。

SQL 文件完整展示后，通过 `mysql_tunnel PROFILE --file=FILE` 执行，并展示带注释的实际 Bash 调用。远端 Bash 文件通过 `/path/to/ssh-connect TARGET bash -s < FILE` 执行。dump CLI 文件完整展示 Bash 调用，并以注释列出筛选语义的 SQL；utility 动态生成的内部 SQL 不应被伪称为已全部列出。

SSH 使用本技能的 [ssh-connect](scripts/ssh-connect)，展示命令时写出实际路径。使用 `keychain-pkcs11` 标准 ECDSA（`secure-ecdsa`）时，通过 `--secure-ecdsa-dir DIR`（或 `--pkcs11-module PATH --pkcs11-pubkey PATH`）让 `ssh-connect` 自动管理独立 `ssh-agent`、过滤无关 CTK 身份并在退出时回收，无需手工拼接 `ssh-agent` 命令，也不要再额外传 `-E`。用户已要求“先展示再连接”时，在同一轮先展示完整内容和命令，随即发起连接并等待本机指纹验证；用户明确要求等文字确认时才等待该确认。SSH 或 SQL 收到 `SSH_AUTH_REJECTED` （退出码 77）后报告拒绝并结束本次操作。诊断为 `agent refused operation` 时报告本机代理拒绝签名，只有用户或认证组件明确确认时才归因为取消指纹。收到 `SSH_SIGNING_FAILED` 时报告签名失败及原因未确认。两种情况均等用户重新授权再试。

一个事务所需的多条 SQL 可以放在同一个文件。执行后汇报实际结果并清理临时操作文件，保留用户要求的导出成果。此 skill 是 agent 行为约定，系统级权限控制由运行环境实施。
